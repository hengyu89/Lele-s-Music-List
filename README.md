# 哇啦哇啦稀里哗啦的歌单

为哇啦的直播观众准备的歌单网页。当前从哇啦提供的 Word 歌单导入了 1122 首不重复歌曲，保留原文的歌名、歌手和排列顺序。支持歌名、歌手、拼音和首字母搜索，完整歌手列表（按收录歌曲数或名称拼音正序、倒序排列）、精确字数筛选、参考风格筛选、歌名首字母筛选、收藏、随机选歌和复制点歌口令。歌手、字数和风格均可累加选择：同一类中显示任一选中项的歌曲，不同类别同时生效；歌名首字母可选一个，并与其它条件同时生效。分类行可以清除全部条件，筛选弹窗标题旁可以只清除当前类别。

歌曲列表会分批显示，每次加载 60 首，因此放入 1000+ 首歌时也不会一次生成上千个页面元素。

项目文件按用途放置：

```text
index.html              页面入口，供 GitHub Pages 直接访问
css/styles.css          页面样式
js/app.js               搜索、筛选和交互逻辑
js/songs.js             从 Word 歌单生成的歌曲数据
scripts/import_docx.py  重新导入歌单的工具
```

以后增加页面时，可在根目录增加页面文件并共用 `css/`、`js/`。若要加入粉丝账号、评论和管理员功能，再为服务端 API、数据库与身份验证建立相应目录；仅整理前端文件并不会提供这些功能。

风格标签由 `js/app.js` 中的人工整理清单提供。它们是供找歌使用的参考，未标注风格的歌曲依然保留在“全部”中。增删标签时请核对具体歌曲，尤其是“短视频热歌”这类会随时间变化的称呼。

## 本地预览

这是一个无构建依赖的静态网站。可在仓库目录启动静态文件服务器：

```powershell
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 维护歌单

所有歌曲都在 `js/songs.js` 的 `window.WALA_SONGS` 数组中。每首歌的数据格式是：

```js
{
  title: "歌名",
  artist: "歌手",
  pinyin: "ge ming geming gm"
}
```

如果要从相同格式的 Word 文档重新导入，安装 `python-docx` 和 `pypinyin`，执行 `python scripts/import_docx.py "路径/哇啦的歌单.docx"`。脚本按 Word 中相邻的歌名与歌手片段成对读取，合并完全相同的记录，并生成拼音索引。

## 发布到 GitHub Pages

在 GitHub 仓库的 **Settings → Pages** 中，将来源设置为 **Deploy from a branch**，选择 `main` 分支和根目录 `/`。推送文件后等待 GitHub 生成公开网址。发布前请核对歌曲内容与哇啦的意愿。
